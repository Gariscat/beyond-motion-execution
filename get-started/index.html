Get Started

Set up the training environment and the simulation server, download the datasets, then run a vision-language-action policy on the benchmark. The evaluation example uses a π0.5 checkpoint on Task 01 (Pour Flask to Cylinder); other tasks and checkpoints only change the arguments.

1Environment Setup

Training and evaluation use separate environments, so the policy’s packages do not share a process with Isaac Sim. Set up three:

  • Training environment — OpenPI, used to fine-tune a π0.5 checkpoint on the training set.
  • Server environment — Isaac Sim, cuRobo, and the simulation server from GenManip. It executes episodes and computes scores.
  • Client environment — genmanip-client (gmp), installed into the training environment so that environment can submit jobs and serve the policy.

Prerequisites

  • A Linux workstation. OpenPI is tested on Ubuntu 22.04, which is also the system GenManip’s install guide targets.
  • An NVIDIA GPU. For OpenPI, inference needs more than 8 GB, LoRA fine-tuning more than 22.5 GB, and full fine-tuning more than 70 GB. The simulation server can use a second GPU, or share one GPU with the policy server; see the memory note under Serve the policy.
  • CUDA 12.1 for the server environment, and a driver compatible with that toolkit.
  • Isaac Sim 4.1, either already installed on the machine or installed into the server environment below. The evaluation commands on this page call /isaac-sim/python.sh.

The commands use GENMANIP_PATH for the GenManip checkout and POLICY_PATH for a checkpoint directory. That directory contains params/ and normalization statistics at assets/…/norm_stats.json. The evaluation example reads them from assets/merged_500.

Training environment

Clone OpenPI with its submodules and install it with uv. GIT_LFS_SKIP_SMUDGE=1 is required because the install pulls LeRobot.

git clone --recurse-submodules https://github.com/Physical-Intelligence/openpi.git
cd openpi
GIT_LFS_SKIP_SMUDGE=1 uv sync
GIT_LFS_SKIP_SMUDGE=1 uv pip install -e .

The training set is already in LeRobot v2.1. Each task folder is its own dataset root, so a training config should point at one task folder, not at the repository root. Add a TrainConfig for that folder in src/openpi/training/config.py, compute normalization statistics, then fine-tune. Replace <config_name> with the config you added.

uv run scripts/compute_norm_stats.py --config-name <config_name>
XLA_PYTHON_CLIENT_MEM_FRACTION=0.9 uv run scripts/train.py <config_name> --exp-name=my_experiment --overwrite

Training writes checkpoints under checkpoints/. Set POLICY_PATH to the checkpoint you will serve. The evaluation example uses the config name pi05_task06_remove_centrifuge_tubes_500_h50; another task uses its own config name and the same checkpoint layout.

Server environment

Clone the simulation server and record its path:

git clone https://github.com/InternRobotics/GenManip.git
cd GenManip
export GENMANIP_PATH="$PWD"

Install Isaac Sim 4.1 and a matching PyTorch build into this environment:

export CUDA_HOME=/usr/local/cuda-12.1
pip install isaacsim==4.1.0 isaacsim-extscache-kit==4.1.0 isaacsim-extscache-kit-sdk==4.1.0 isaacsim-extscache-physics==4.1.0 --extra-index-url https://pypi.nvidia.com
pip install torch==2.4.0 --extra-index-url https://download.pytorch.org/whl/cu121

If Isaac Sim is already installed, skip that install and run server commands with /isaac-sim/python.sh, which is what the evaluation steps below do.

Then install cuRobo and the repository requirements in the same environment:

mkdir -p saved/envs
git clone https://github.com/NVlabs/curobo.git saved/envs/curobo
pip install -e saved/envs/curobo --no-build-isolation
pip install -r requirements.txt

Copy the validation example so that its saved/assets, saved/tasks, and task config land at those same paths in this checkout. The download does not include the simulator.

Client environment

Install the client into the training environment, beside OpenPI. It stays out of the server environment.

git clone https://github.com/InternRobotics/genmanip-client.git
cd genmanip-client
uv pip install -e .
gmp --help

uv pip uses the OpenPI environment. In a separate client environment the same install is pip install -e ..

Verify

Confirm both sides answer before submitting a job:

# Server environment
cd "$GENMANIP_PATH"
/isaac-sim/python.sh ray_eval_server.py --help

# Client environment
gmp --help

2Dataset

Demonstrations and the published validation example are separate Hugging Face datasets. The evaluation episodes used in Run evaluation are not in these downloads.

Training set

InternRobotics/WET-OP-Bench-Train contains 7,000 simulated demonstrations for 14 tasks, 500 episodes each. The robot is Lift2. Each task folder is its own LeRobot v2.1 dataset, with four RGB cameras, robot state, actions, and a language instruction. Frames are 640×480 at 15 fps.

huggingface-cli download InternRobotics/WET-OP-Bench-Train \
    --repo-type dataset --local-dir WET-OP-Bench-Train

Validation set

InternRobotics/WET-OP-Bench-Validation is one Task 01 initialization example: the flask-to-cylinder scene, robot assets, task configuration, and saved initial state. It has no recorded trajectory. It is not the full validation set and not the 680-episode evaluation set.

huggingface-cli download InternRobotics/WET-OP-Bench-Validation \
    --repo-type dataset --local-dir WET-OP-Bench-Validation

3Run evaluation

With the environments and data in place, a run has four parts: the simulation server, a job submitted through gmp, a policy served over websocket, and one or more workers that connect the two.

  • Start the evaluation server

    The server loads Isaac Sim, executes episodes and computes scores. It keeps running across jobs.

    cd "$GENMANIP_PATH"
/isaac-sim/python.sh ray_eval_server.py --host 0.0.0.0 --port 8087

    Wait until http://127.0.0.1:8087/status answers; the first startup can take several minutes.

  • Submit a benchmark job

    From the policy environment, submit one task or list several targets. A run_id names the run and determines where results are written.

    # One task: Task 01, all 40 test episodes
gmp submit scientific_experiments/task_01_pour_flask_to_cylinder/test \
    --run_id my_first_run --host 127.0.0.1 --port 8087

# Full benchmark: pass all 20 task targets, e.g.
#   scientific_experiments/task_01_pour_flask_to_cylinder/test ... task_z6_evaporative_crystallization_prep/test

    Demonstrated tasks (01–14) run 40 episodes across the C-only, B-only, I-only and Mixed test settings; zero-shot tasks (z1–z6) run 20 Mixed episodes each. Episodes are claimed through server-side locks, so additional workers and repeated submissions skip completed episodes instead of duplicating them.

  • Serve the policy

    Expose the checkpoint through OpenPI’s websocket policy server:

    python scripts/serve_policy.py --port 18100 \
    policy:checkpoint \
    --policy.config pi05_task06_remove_centrifuge_tubes_500_h50 \
    --policy.dir "$POLICY_PATH" \
    --policy.norm-stats-dir "$POLICY_PATH/assets/merged_500"

    The server is ready when http://127.0.0.1:18100/healthz responds. On a single shared GPU, prevent the policy framework from pre-allocating all memory so the simulator still fits:

    export XLA_PYTHON_CLIENT_PREALLOCATE=false
export XLA_PYTHON_CLIENT_MEM_FRACTION=0.40

  • Connect evaluation workers

    Each worker rolls out episodes: it pulls observations from the simulation server, queries the policy for action chunks and steps the environment. Start one worker per GPU capacity slice; two workers per server is a typical setting.

    python scripts/pi05_task05_client.py \
    --worker_ids 0 \
    --run_id my_first_run \
    --horizon 30 \
    --head_camera overlook \
    --eval_host 127.0.0.1 --eval_port 8087 \
    --model_host 127.0.0.1 --model_port 18100

    The control setup used for the reported results: joint-position actions, a fixed overlook head camera, a model action horizon of 50 with replanning every 30 steps. Workers exit on their own once every episode of the submitted job is done.

  • Read results

    Track progress while the job runs and inspect per-episode outcomes afterwards:

    gmp status --host 127.0.0.1 --port 8087

# One result_info.json per episode, with success and stage-wise scores:
saved/eval_results/scientific_experiments/<run_id>/

    An episode is complete when its result_info.json exists; Task 01 is done at 40 files, the full benchmark at 680. Each file records binary success and the stage-wise, skill-aligned scores described on the overview page.
